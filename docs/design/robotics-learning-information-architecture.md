# Robotics Learning Platform 信息架构

## 用户主线

平台主线只有五个阶段：

1. **创建项目**：选择机器人、任务、模型契约和目标设备。
2. **准备数据**：在线仿真录制，或导入离线 JSONL 数据集。
3. **训练策略**：在线强化学习或离线行为克隆。
4. **验证策略**：仿真回放、真机遥测和虚实对比。
5. **部署运行**：板卡预检、受控发布和运行反馈。

每个阶段只负责自己的输入、输出和阻断条件。页面只能有一个主操作，辅助操作放入详情或工具区。

## 模块边界

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| 项目 | 项目上下文和契约 | 训练执行、设备控制 |
| 数据 | 仿真录制、轨迹导入、数据集版本 | 策略训练 |
| 训练 | 在线 RL、离线 BC/Offline RL 任务 | 真机发布 |
| 验证 | 回放、遥测、评测报告 | 修改模型参数 |
| 部署 | 预检、发布、运行状态 | 生成训练数据 |
| Agent | 查询状态、编排已存在的动作 | 绕过阶段前置条件 |
| 记录 | 运行、审计和错误历史 | 重新执行副作用动作 |

## 指引规则

- 首屏只解释“现在在哪一步”和“下一步做什么”。
- 内部状态（ledger、attestation、runner）放到详情，不放在主指引句子里。
- 设备离线时，仍允许进入数据和训练阶段；只有部署运行被阻断。
- 合成数据必须明确标注为演示证据，不能改变真机发布状态。
- Agent 的回答必须包含结果文本；只有工具执行状态时，显示“执行完成，暂无文本结果”。

## 前端拆分顺序

后续按以下边界拆分 `public/app.js`：

- `workspace-context.js`：项目、模型、设备和任务上下文。
- `workflow-navigation.js`：五阶段导航和前置条件。
- `dataset-workflow.js`：录制、导入和数据集版本。
- `training-workflow.js`：在线与离线训练提交、轮询和结果。
- `evaluation-workflow.js`：回放、遥测和评测摘要。
- `deployment-workflow.js`：预检、发布和反馈。
- `agent-chat.js`：Agent 对话和消息状态。

拆分期间保持现有 API 路径和 DOM id 不变，避免一次性改动影响线上部署。
