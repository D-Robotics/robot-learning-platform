03 / INDEPENDENT PLATFORM

一站式体验，不是一进程

Sim2Real 独立运行 · RDK Studio 可选接入
最合理的边界是“平台独立、入口互通”。 Sim2Real Lab 自己拥有项目、模型、运行和部署台账； RDK Studio 通过 Skill / MCP / API 调用它，但不复制一套业务逻辑。RoboGo 只是可插拔的云端训练后端， 本地 Agent 则负责 GPU、文件、USB/SSH 和 RDK 板卡等需要在用户环境执行的动作。
OPTIONAL FRONTEND RDK Studio 对话、Plan/Spec/Execute、审批与证据卡
→
AI ADAPTER 外部 Skill + MCP 可选装配；Skill 编排步骤，MCP 只包装公开 API
→
CANONICAL API Sim2Real API 唯一业务契约：项目、模型、训练、制品、预检
→
CONTROL PLANE 台账 / 事件 / 权限 owner 隔离、幂等、状态回写、审计
EXECUTION A Local Agent 服务器 GPU、模型文件、真实 RL worker；无 GPU 时运行 Mock
EXECUTION B RoboGo Connector 显式发起云端任务、同步 runId / 状态 / checkpoint；不自动 fallback

两个执行后端都回到同一条证据链：run → artifact → RDK preflight → no-motor Canary → 人工批准的 Live

图：浏览器只是入口之一；API 才是平台真源，Skill/MCP 是 RDK Studio 的适配层，Local Agent 与 RoboGo Connector 是可替换执行器。本公开仓库不包含 DSH Skill 或 MCP 实现，未装配时网页/API 仍可独立运行。

多用户身份边界：生产环境由经过验证的 Studio SSO 网关/adapter 提供身份， Sim2Real 只接收稳定的 accountId 和服务端短时 token。业务路由通过 Sim2RealAuthPort 工作，不读取 Studio React 状态、对话记录或业务台账；当前公开 standalone unit 采用签名 trusted-proxy 参考实现，未来接入标准 OIDC 时只替换认证适配器。 未登录请求直接返回 401，模型、运行、设备和部署记录按账号隔离。
单实例保护与异常恢复：JSON 台账最多保存 100 个自定义模型、10,000 个 run、 200 个部署计划和 768 MiB；遥测另有按 run/账号的样本与字节上限，超限返回 413 SIM2REAL_TELEMETRY_QUOTA_EXCEEDED；整个 ledger 字节上限返回 507 SIM2REAL_STORAGE_QUOTA_EXCEEDED，模型/run/部署记录数上限返回 507 SIM2REAL_LEDGER_QUOTA_EXCEEDED，不会静默删除历史。local/RoboGo 的 queued/running 任务默认按账号限制 4 个并发（可由 RDK_SIM2REAL_MAX_ACTIVE_RUNS 调整，最大 100），幂等预留和检查在同一写入链中完成。 若 runner 已受理但提交响应超时/连接断开，或进程在保存 externalRunId 前崩溃， 结果会保留为 queued 的 outcome unknown；确认任务归属后调用 POST /api/sim2real/runs/:id/reconcile，以 {"externalRunId":"…","confirm":true} 只读查询并原子补回状态；不会重新启动任务。 这些是 MVP 保护阀，生产多人部署仍需数据库、对象存储和租户配额服务。
API

API 是机器契约

公共客户端使用版本化 /api/v1/duck/...；现有 /api/sim2real/... 保留为向后兼容别名。两套路径由同一业务路由和同一台账/鉴权适配器提供；网页、CLI、RDK Studio 和未来客户端都调用同一套接口。

MCP

MCP 是 AI 适配器

部署方可选装 microduck-mcp 来转发 API 并投影状态/证据；Plan/Spec 只读，Execute 的训练和部署动作必须经过审批。该适配器不随公开仓库发布。

SKILL

Skill 是流程剧本

部署方可用账号隔离的 DSH Skill 描述“先仿真、再训练、再预检”的步骤，不把模型校验、 权限和业务状态塞进 Skill 文本。该 Skill 不随公开仓库发布。

04 / CONTRACT

公共底座：双产品契约适配

无论是 RoboGo 还是本地训练，训练后端收到的都是当前产品的一份已校验 JSON。 MicroDuck 使用固定官方契约；RDK Duck 使用你们真实模型的 manifest 契约。这样训练来源可以变化， 仿真、评测、板端兼容性和部署台账不会漂移，也不会把 MicroDuck 的维度误套到 RDK Duck。

PATH B / ROBOGO
