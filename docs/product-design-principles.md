# 工作台交互设计原则与审查

本文件把通用设计原则转成 RDK Robot Learning Platform 的可检验要求。适用范围是
浏览器工作台、流程引导与状态展示；沿用
[D-002 子界面决策](decisions/D-002-flow-child-subinterface-states.md) 的真实模块切换，
以及现有账号、设备、审批和运动门禁。

本轮为 2026-10-13 的源码与软件行为启发式审查，导航反例基于 `fbc2f28`。
没有进行参与者访谈、任务完成率研究或实体运动验收。下文“改进”是验收要求，
完成情况须绑定最终提交和本次测试输出，不能据此宣称已经上线或真机通过。

## 原则来源

- Jakob Nielsen 的 [10 Usability Heuristics](https://www.nngroup.com/articles/ten-usability-heuristics/)
  提供系统状态可见、一致性、错误预防、用户控制和错误恢复的检查视角。
- GOV.UK 的 [Government Design Principles](https://www.gov.uk/guidance/government-design-principles)
  强调用户需要、使用情境、减少复杂度和用实际证据迭代。
- Vitsœ 的 [Dieter Rams: Good design](https://www.vitsoe.com/us/about/good-design)
  提供实用、易理解、诚实与聚焦必要内容的设计取向。

以下六条是这些原则在本工程平台中的应用，不是原文翻译，也不是用户研究结论。

## 六条可检验要求

### 1. 先呈现用户要完成的事

首屏显露“仿真与数据 / 模型训练 / 设备接入”三条主要流程，说明产出与进入位置。
具体工具和高级参数在需要时展开，保留原有能力和旧深链接；不要求初学者先记住
引擎、模型格式与板端实现的内部名称。

检查：首次进入与窄屏下都能找到三条流程；每条入口打开对应实际模块。
仍保持既定视图和侧栏子项结构，高级设置折叠不清空已填写的值。

### 2. 每个步骤都能继续，缺少前提时能知道怎样补齐

步骤显示当前状态、所需材料和下一步动作。可用动作进入实际工作区；不可用动作
在同一位置说明具体缺项，并提供选择设备、登录、准备模型或重新检查的入口。
“查看”“准备”“运行”使用不同动词，打开面板不得隐式提交任务或启动设备。

检查：空项目、未选设备、缺模型、资源不可用和服务失败都有可读原因与有效入口；
只打开引导或切换步骤时，任务提交与运动请求数量为零。

### 3. 显示正在发生的事，保持证据对象一致

训练引导和进度优先反映当前上下文中排队或运行的训练；已经完成的模型契约检查
不得遮住活动训练。任务状态未知时提示找回原任务，避免引导重复提交。
模型、项目、设备或账号切换后，旧异步回执不能覆盖新上下文。

检查：同时存在完成的契约检查与活动训练时，下一步和进度指向同一个训练 Run；
覆盖排队、运行、失败、取消、未知状态，以及延迟响应晚于上下文切换的情况。

### 4. 同一位置只有一套导航状态

可见模块、页签选中态、横幅、面包屑、浏览器标题和地址保持一致。
侧栏、页签、流程引导和通用入口都使用同一状态转换；刷新与浏览器返回能恢复
目的模块。损坏的地址安全回到可用入口，不中断页面初始化。

检查：覆盖全部既有深链接、同级切换、跨视图返回、设备站模块切换、裸视图入口、
损坏编码和不匹配的视图/子项组合。保留 D-002 的互斥面板与同级历史替换规则。

### 5. 有后果的操作显示真实对象，并由原门禁裁决

运动确认显示本次操作实际使用的设备标识、板卡型号与已加载策略 SHA，无法取得
真实值时说明缺项。确认期间上下文变化须失效或重新确认；停止动作继续指向实际
运行对象。页面说明和确认不能代替服务端权限、审批与板端安全限制。

检查：使用软件替身验证目标标识、型号和策略一致，缺项不能显示示例值；
覆盖确认前后切设备、晚回执、账号变化和停止目标。此检查不启动实体运动。

### 6. 结果诚实，失败后有可恢复的路径

区分预置模型、mock、只读准备报告、软件部署记录和实体现场证据。
操作完成、模型加载或命令归零分别描述其实际结果；不将其标为已校准、已站稳、
已行走或已完成跟随。失败提示保留问题与恢复入口，输入和已有记录继续可用。

检查：准备检查通过仍显示实体校准待验；相机出图仍显示跟随输入缺项；
错误和未知状态不升级为完成。成果导出保留来源和项目归属边界，排除敏感连接信息。

## 本轮已复现的导航问题

以下反例通过当前工作台源码和既有 DOM 测试环境复现，没有连接板端。
源码入口为 [app.js](../services/sim2real-web/public/app.js)，
回归测试放在 [ui-behavior.test.ts](../services/sim2real-web/ui-behavior.test.ts)。

| 问题与用户影响 | 触发反例和源码原因 | 对应改进与最窄验证 |
| --- | --- | --- |
| 设备站模块切换后，位置仍显示设备管理；刷新丢失目的模块 | 从 `#station/devices` 点击诊断页签，实际模块为 `diagnostics`，地址、横幅、标题和侧栏仍为设备管理。`setStationModule` 只更新模块属性与页签；页签处理器没有同步流程上下文 | 将设备站模块纳入统一导航状态，保留旧 `devices` 深链。断言切换后的模块、标题、选中态与地址一致，并能刷新及返回恢复 |
| 从通用入口回到评测时，选中页签与实际面板不一致 | 从 `#evaluate/comparison` 转到记录，再经工作流入口返回评测，实际面板为 comparison，run 页签却声明选中。`setView` 先套默认分区，再直接恢复 sticky 模块属性；没有同步全部页签状态 | 用相同模块状态转换恢复既有评测、部署子页。对裸 `#evaluate`、`#deploy` 和通用入口立即断言内容、页签、横幅、标题及地址，不能等待轮询修正 |
| 无效深链接中断初始化或选中错误流程 | 初始 `#train/%` 抛出 `URI malformed`；`#simulate/prepare` 显示仿真面板，却把模型与兼容性标为当前入口。`parseHashLocation` 未保护解码，也未核对视图与子项归属 | 解码失败安全恢复，并校验合法组合。断言异常地址不抛错、工作区加载完成、当前入口唯一；全部旧合法深链仍恢复原目的模块 |

## 本轮其他交互改进的验收方向

| 改进要求 | 应保留的行为 | 反例验证 |
| --- | --- | --- |
| 显露三条主要流程 | 旧工具、专业设置与流程深链仍可达 | 首访、窄屏和键盘访问均能进入三条流程 |
| 步骤给出下一步动作与缺项解释 | 查看步骤不提交任务、不运动 | 缺账号、设备、模型或资源时，有原因及对应入口 |
| 活动训练不被完成的契约检查遮住 | 契约检查记录继续可查 | 较新的契约检查与较早的 queued/running 训练同时存在时，进度仍指向训练 |
| 运动确认显示真实目标上下文 | 权限、审批、限幅、停止与传感器门禁继续生效 | 缺真实目标信息、切设备和晚回执不能沿用旧确认 |
| 软件完成与实体验收分别表达 | 预置、mock 与项目来源继续标注 | 准备通过、策略加载或部署完成均不自动宣称真机行走通过 |

## 验证边界

- 状态派生与选择逻辑先跑对应纯函数测试；导航、失败恢复、上下文隔离跑工作台 DOM
  行为测试。UI 修改前后运行 `npm run verify:ui`，不放宽棘轮预算。
- 在隔离存储的浏览器实例中走主路径，检查实际显隐、窄屏、键盘与返回操作；
  读屏体验沿用 [人工验收清单](ui-screen-reader-checklist.md)。DOM 断言不能代替这些检查。
- 发布验证按 [生产运维文档](production-operations.md) 与项目完整门禁执行；
  软件测试或上线成功不构成硬件验证。板端校准、停止保护、跌倒处理、实体试走和跟随
  仍需现场流程及独立证据，不能由本次启发式审查补齐。
- 后续参与者任务测试应记录任务目标、阻断位置、恢复方式和实际结果，再判断本轮
  改进是否降低理解与操作成本；本次不填写未经测量的完成率、耗时或满意度。
