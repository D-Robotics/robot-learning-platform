# 读屏人工验收脚本（VoiceOver / NVDA）

自动化能证明的东西已经证明完了：`ui-responsive.spec.mjs` 会读 Chromium 的无障碍树，
断言地标齐全、52 个交互控件都有可访问名、tablist 暴露选中态、装饰字形不进树、
标题大纲层级不跳级。**但"听起来顺不顺"只有人听得出。** 这份脚本是给做这一步的人用的，
不是给 CI 用的。

预计 15–20 分钟。

## 环境

- macOS：`Command + F5` 开 VoiceOver。第一次开会有引导，建议选"仅使用 VoiceOver 键"。
- 关闭语速调整，保持默认（`VO + Command + 左右方向` 可调）。
- 服务：构建产物在 `dist-server/`，**改完源码要先 `npm run build`**，
  然后打开 <http://127.0.0.1:18102/>。
- 建议先 `localStorage.removeItem('rdk-duck-lab-onboarding-v1')` 再看引导流程那一节。

VoiceOver 键记作 `VO`（默认 `Control + Option`）。

---

## 1. 首屏与地标

1. 页面加载完，按 `VO + U` 打开转子（Rotor），选"地标"。
   - 期望：能听到 **banner / navigation ×5 / main / contentinfo**，且 5 个 navigation
     都有区分性名字（`平台导航`、`工作台导航`、`机器人学习流程`、`研发闭环阶段`、
     `闭环进度`）。
   - 逐个跳过去，确认没有哪个地标是"未命名"。
2. 转子切到"标题"。
   - 期望：第一项是 **1 级标题**「RDK Robot Learning Studio · 机器人学习工作台」，
     其后是 2 级、3 级，**没有跳级**。
3. 按 `VO + 左方向` 从 `main` 往回读，确认顶栏的 4 个阶段（仿真与录制 / 强化学习训练 /
   Sim2Real 评测 / 部署与反馈）**被读成状态而不是按钮**（不应听到"按钮"），
   当前所在的那个应报出"当前步骤"之类的当前态。

## 2. 导航与抽屉

4. 侧栏逐个读过去。
   - 期望：9 项，每项读"名称 + 副标题"，当前页读作**当前页**（`aria-current="page"`）。
   - 期望：**不朗读 `◇` `✦` `▣` `▦` `⌂` 这些字形**。如果听到"白色菱形""黑色菱形"，
     就是装饰字形泄漏回无障碍树了。
5. 窗口缩到 900px 宽，按 `Tab` 找到顶栏最左侧的 ☰ 按钮（应读"打开导航菜单"）。
   - `Enter` 打开：期望焦点**落在抽屉内**、读屏能读到抽屉里的导航项。
   - `Escape` 关闭：期望焦点**回到 ☰ 按钮**，并读"关闭导航菜单"已变回"打开"。
   - 抽屉打开时试着 `Tab` 出去，期望**出不去**（背景已被 `inert`）。

## 3. 新手引导

6. 清掉 localStorage 后刷新（首访）。
   - 期望：9 秒内弹出 12 步指引，焦点进入对话框，**先读标题和正文**，不是直接读"下一步"。
   - `Tab` 循环 20 次以上：期望**始终在卡片内**（关闭 / 跳过 / 上一步 / 下一步）。
   - `Escape` 关闭：期望焦点回到打开它的元素。
7. 刷新后**立刻滚动页面**，再等 3 秒。
   - 期望：指引**不再自动弹出**（用户已开始操作就不打断）。顶栏「新手指引」按钮仍可打开。

## 4. 无障碍树里最容易出问题的三处

8. **命令面板**：`Command + K` 打开，输入"训练"。
   - 期望：焦点留在输入框，方向键上下移动时**读屏播报当前选中项的名称**。
   - 期望：按 `Tab` **直接离开面板**，不是逐个遍历 11 个命令。
9. **训练页 / 设备页的 tab**（`数据工作台` `模型契约` / `设备连接` `遥测概览` …）
   - 期望：每个 tab 读出**选中/未选中**状态。
   - 期望：整组 tab 只占**一个 Tab 停靠点**；进入后用 `←/→` 在组内移动，
     焦点跟随时立即切换面板。
   - `Home` / `End` 跳首尾。
10. **顶栏「更多」菜单**：`Enter` 打开后按 `↓`，期望焦点移到第一项；
    再按 `↓` 逐项移动；`Esc` 关闭并把焦点还给「更多」。
    「通知关/开」这一项应读作**复选框**（"未勾选/已勾选"），
    不应同时报出两种开关状态。

## 5. 异步状态是否被播报

11. 在训练页触发一次任务（或等已有任务状态变化）。
    - 期望：任务状态**从排队到运行到完成**的中间变化会被播报（`运行状态` 是 live region）。
    - 期望：Agent 抽屉里的工具事件、toast 提示也会播报，且**不刷屏**。

## 6. 空状态与诚实文案

12. 评测页 / GPU 资源页（数据为空时）。
    - 期望：读出来的是「平台不会用默认值冒充评测结果」这类**说明性文案**，
      不是空白或"—"。这一条是产品刻意做的，值得确认它在读屏下也成立。

## 记录方式

每个编号记三种结果：**通过 / 失败（贴出读屏原文）/ 无法判断**。
失败项请带上 VoiceOver 的原文播报，那是唯一能定位问题的线索——
"听起来怪"没法修，"它读了『白色菱形 仿真与录制』"可以。

## 已知的、自动化覆盖不到的点

- **阅读顺序 vs 视觉顺序**：CSS 重排（flex/grid order）不会改变 DOM 顺序，
  读屏按 DOM 读。当前布局未使用 `order`/`row-reverse` 重排内容，
  但这一条需要人在第 1 节里顺带确认一遍。
- **播报时机**：live region 的 `polite` 是否被更频繁的更新淹没，只能听。
- **中文分词与英文缩写混读**：`upstream-browser`、`NO MOTOR`、`BoardAgent`
  这类词在不同语速下的可懂度，需要人判断。
