# 0.3.2：浏览器确认后插件仍未登录

## 现象与定位

用户反馈 0.3.1 浏览器显示连接已确认，但插件仍返回 LOGIN_REQUIRED，查询过程中连接码反复变化。

源码存在可复现的生命周期缺陷：未领取的授权只保存在进程内存；MCP 进程退出后丢失原挑战。状态查询在没有会话时还会自动开始新挑战。已登录会话的缓存存在，并不覆盖“浏览器已确认、插件尚未领取”这一阶段。线上未确认挑战的公开 start/poll 协议检查返回 200/202，不能据此断言受影响账号的完整授权链路已经通过。

## 修复

- 待确认挑战按目标平台隔离保存，使用私人目录、文件权限与原有缓存校验；Windows 使用 CurrentUser DPAPI 和安装目录绑定，不回退明文。
- 新进程恢复原挑战，状态查询只领取或验证已有授权，不自动创建新挑战。
- 显式登录复用当前有效挑战或已验证会话，确认成功后保存会话并移除挑战。
- 临时网络或服务故障保留挑战；过期后状态查询不会换码。退出登录删除会话与挑战，进行中的旧领取不能恢复已退出会话。
- 身份回执异常或账号不匹配保持阻断，明确报告，不清缓存后反复请求登录。

## 升级与验收

使用 0.3.2 未配置分享包，运行本系统安装入口并刷新实际 MCP 连接。核对实际加载版本与源码摘要后调用一次 rdk_auth_login，浏览器确认同一码，再调用 rdk_auth_status。应返回 authenticated=true；重复查询和 MCP 重连后仍保持同一账号，不出现新码。旧版尚未落盘的内存挑战无法由新版恢复，需要在新版发起一次新授权。

回归包括状态查询无写入、六次对象重建复用挑战、真实 Node 进程退出后领取授权、已有会话重复登录、过期、临时轮询失败、跨授权实例退出与旧领取竞争，以及异常身份回执。全部使用隔离合成账号，不涉及训练或真机。

没有在反馈者的 Windows 安装和账号上直接复测；Windows 原生端到端仍待确认。不得把上述隔离通过写成该账号已经恢复，或把原有 macOS 的训练验收沿用为 0.3.2 新一轮真实训练验收。
