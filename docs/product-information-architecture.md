# 产品信息架构

## 目标

平台围绕“完成并交付一项机器人策略”组织，而不是围绕实现方式或后端组件组织。用户始终处在一个项目上下文中，沿着一条策略血缘推进：

```text
项目 → 机器人 + 任务 → 数据 / 仿真 → 训练 Run → Artifact → Evaluation → Deployment
```

## 一级工作区

### 工作区

负责选择项目、机器人和任务，显示当前目标、阻断原因、最近 Run、最新评测和设备状态。它是全局上下文入口，不承载具体执行细节。

### 构建策略

把数据、仿真、轨迹、训练、模型契约和评测放在同一条构建路径中。训练页展示 Run 与 Artifact 的关系，评测页展示 Evaluation 与其输入 Artifact、数据和设备的关系。

### 交付到设备

设备管理、只读预检、发布闸门、运行反馈和回滚属于一次交付动作。设备详情和部署详情必须互相链接，并共享目标设备、Artifact 和发布状态。

### 证据中心

证据中心是横向审计视图，不是流程中的额外步骤。它统一检索 Dataset、Run、Artifact、Evaluation、Telemetry 和 Deployment，并能沿血缘回到产生它的页面。

## 聚合与分散规则

| 应聚合 | 原因 |
| --- | --- |
| 项目、机器人、任务 | 共同定义用户要解决的问题 |
| 数据、仿真、轨迹 | 共同构成策略输入 |
| Run、模型、Artifact、Evaluation | 共同构成一次策略迭代 |
| 设备、预检、发布、反馈、回滚 | 共同构成一次受控交付 |

| 应分散 | 原因 |
| --- | --- |
| 证据中心与执行流程 | 审计视角要独立，不能阻塞主流程 |
| 执行资源与业务对象 | GPU、Worker、BoardAgent 是实现资源，不是用户目标 |
| Agent 与业务导航 | Agent 是操作方式，可以跨所有工作区工作 |
| 设备运维与策略构建 | 设备健康可独立检查，不应被训练流程绑架 |

## 页面上下文规则

1. 每个页面都显示当前项目、机器人、任务。
2. Run、Artifact、Evaluation、Deployment 的详情必须显示完整血缘链。
3. 从证据中心打开对象时，保留来源上下文，并提供“回到流程”动作。
4. 执行资源只作为提交训练、评测或发布时的选择器出现。
5. Mock、真实、受限和待接入是状态标签，不作为一级导航分类。
6. 所有阻断状态必须同时给出原因、影响、修复动作和责任对象。

## 状态与动作

页面主动作只表达用户目标，例如“发起训练”“创建评测”“生成预检计划”“发布到设备”。本地 worker、GPU、RoboGo、BoardAgent 等执行方式显示在动作后的配置和状态区域，不抢占主导航。
