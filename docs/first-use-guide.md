# 第一次使用工作台

这份文档面向使用网页版工作台的用户。安装和启动服务请看[首次启动与部署向导](./first-run.md)。首页先推荐一次浏览器体验：操作示例机器人，录下动作数据，再查看记录。点击“打开示例机器人”即可开始，不需要先理解整套训练和部署流程。

## 默认从示例开始

首页主卡片只提供当前任务的一个执行按钮，按实际进度提示打开示例、查看记录或继续当前步骤。“体验步骤”默认收起，展开后可以阅读步骤和完成情况；步骤清单本身不提供执行按钮。

已有设备或模型时，展开“我已有设备或模型”，再选择“连接我的 RDK”或“使用已有模型”。选择后，该折叠区改名为“换一种开始方式”，步骤折叠区相应改为“设备准备步骤”或“模型准备步骤”。需要返回体验时，也在这里选择。

选择目标会改变首页的下一步提示和任务清单。选择按钮本身不会执行训练、设备连接、部署或运动，也不会替换当前机器人。体验路径始终使用 MicroDuck 示例；当前选择其他机器人时，首页会在主按钮旁说明开始时会切换示例。设备和模型路径沿用当前选择的机器人。

## 在浏览器里体验机器人

这条路径在浏览器中完成，无需连接开发板或配置 GPU。使用示例仍需要部署环境提供可打开的浏览器仿真器。

1. 在首页点击“打开示例机器人”。如果当前选的是其他机器人，首页说明开始时会切换到 MicroDuck 示例。
2. 在示例画面中点击“开始录制”，用方向键操作机器人，再停止录制。示例实际采集这次操作中的观测和动作数据，工作台读取记录后会提示“动作已录下，查看你的记录”。
3. 停止录制后，直接点击仿真画面下方的“查看这段记录”。也可回到首页点击“回看这段记录”。工作台在当前页打开动作记录弹窗，并将焦点移到播放按钮。
4. 点击“播放”，将刚才录下的同一段动作记录完整播放到末尾。首页随后显示“已完成动作录制与记录检查”，可点击“再次查看记录”。

弹窗展示采样时间轴和动作记录，可以查看观测、动作等数据随采样点的变化。关闭或按 Escape 会停止播放并回到刚才点击的按钮，随后可以再次打开记录。此处不重演三维机器人动作，不保证复现当时的机器人画面。

仅打开仿真、加载记录、浏览页面或读完帮助，不会完成体验。重新录制后，需要完整播放新记录；上一段记录的回看结果不会算到新记录上。完成体验表示完成浏览器动作数据录制与记录回看，不表示模型已训练、评测已通过或机器人已部署。

当前浏览器录制保存在页面内存中，浏览器重新加载页面或关闭页面后会丢失，不会自动写入服务器训练或数据账本。如需保存原始记录，请在重新加载页面前使用示例中的“导出 JSONL”。导出文件也不等于已上传数据集或已完成训练。

如果平台已确认 MicroDuck 浏览器示例不可用，首页会提供“查看示例安装指引”。如果能力状态尚未确认，页面不会把它显示成示例已就绪或已确认缺失。服务正在加载时按钮会等待；读取失败时可点击“重新连接”。

## 有自己的设备

例如，你已有一台设备但尚未在平台登记：在首页展开“我已有设备或模型”，选择“连接我的 RDK”，再点击主卡片的“查看如何添加设备”，进入设备页面查看接入方式。添加记录后，还需要按连接指引操作，等待平台确认设备连接成功；设备出现在列表里不代表已经连接。

连接成功后，首页会提示导入模型说明或检查模型兼容性。兼容性通过后，再点击“检查设备使用条件”完成只读预检。预检通过时显示“设备预检已通过”，并提供检查记录入口。

设备预检检查连接、模型等使用条件，不会启动机器人。“设备预检已通过”和“策略已部署到真机”是不同结果。真实部署、低速验收和运动仍需按部署流程确认现场条件并通过服务端门禁；首页任务清单不会代替这些确认。

## 有自己的模型

例如，你已有模型，但不知道能否用于当前机器人：在首页展开“我已有设备或模型”，选择“使用已有模型”，再点击主卡片的“导入模型说明”，进入模型准备区域。该入口接收 manifest JSON 说明，用于登记模型输入、输出和设备要求；填写并登记说明后，再执行兼容性检查。

“登记模型说明”只表示说明已登记，不表示 ONNX 权重已上传或模型已训练。可以直接导入 JSON 说明或使用模板；完整 JSON 默认收起，需要时点击“查看或编辑完整说明”。工作区内置的示例模型不会算成你已登记的模型说明。实际训练、模型制品处理与部署各有独立操作和验收条件。

兼容性通过后，平台根据已有证据提供“了解训练步骤”“查看训练结果”或“查看评测结果”。没有训练或评测结果时，不会凭页面访问记成已有结果；只有训练结果时，也会明确说明尚未确认有评测结果。需要新训练时，应先选择任务模板并准备可用的训练后端。

需要在设备上使用模型时，继续检查设备预检条件。此路径的“模型的设备预检已通过”仍表示只读检查结果，不能当成已经部署或可以直接运动。

设备和模型资料属于账号工作区。游客选择这两条路径时，首页会提示“登录并继续”；浏览器示例体验可以在游客态进行。

## 帮助与进阶信息

“新手指引”是主动打开的四步说明：选择目标、体验录制与记录回看、准备设备或模型、按需要继续训练或真机流程。首次打开工作台不会自动弹出指引。最后的“回到任务”只关闭说明，浏览器本地保存的指引阅读状态不会完成首页任务。

项目、运行记录、研发统计、助手和环境信息放在首页“我的项目与运行记录”折叠区。准备度用于查看项目证据是否齐全，不能据此判断服务健康，也不能代替发布或运动许可。

侧栏“完整工作台”在首页默认收起，进入具体流程后会自动展开；训练、评测和发布等完整入口都保留在其中。“机器人与项目设置”也默认收起，需要切换机器人或项目时再展开。

## 实现与验收边界

首页使用 [first-use-core.js](../services/sim2real-web/public/first-use-core.js) 的 `SimFirstUseCore.plan(input)` 生成说明、步骤和动作键，由 [app.js](../services/sim2real-web/public/app.js) 读取当前状态并在用户点击后执行相应操作。规划函数不执行训练、部署或运动；完成状态只接受明确证据，不通过字符串或数字的真假值推断成功。

用户目标是浏览器偏好，与账号的模型、设备、训练、数据账本分开。首页目标清单只是当前任务的说明，服务端 Golden Path、权限、制品签发和运动门禁仍归服务端路由与 `server/sim2real/` 所有，不由前端目标切换改写。

开发验收先运行：

```bash
npm test -- services/sim2real-web/first-use-core.test.ts services/sim2real-web/ui-behavior.test.ts
npm run verify:ui
```

[first-use-core.test.ts](../services/sim2real-web/first-use-core.test.ts) 检查目标计划、未知能力、加载、错误、登录和证据边界；[ui-behavior.test.ts](../services/sim2real-web/ui-behavior.test.ts) 检查目标选择、页面动作、浏览器录制与记录播放等真实行为；`verify:ui` 检查信息架构、入口和 UI 不变量。

浏览器人工验收应覆盖三类入口、首次访问无弹层、录制后未播放记录、完整播放记录、重新录制后重新确认、浏览器重新加载后的记录丢失，以及设备预检不会触发运动。还需核对记录回看展示的是采样时间轴，不能将其当成三维动作重演。人工读屏仍需按[读屏验收清单](./ui-screen-reader-checklist.md)验收，自动化检查不能代替该项验收。
