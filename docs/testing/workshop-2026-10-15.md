# Workshop 从零到一验收（2026-10-15）

本轮目标覆盖软件学习流程和最终实体站立/行走。现场只有开发板，没有可运行的机器人鸭本体。
因此开发板验收限于隔离目录内的纯推理；实体标定、站立、行走没有执行，也不据软件测试判为通过。

## 本轮修复

| 问题 | 修复与反例 |
| --- | --- |
| Studio 原生插件可导入，但 Agent 未消费插件 MCP | 宿主合并启用插件声明，保留设置优先、禁用、账号隔离、默认审批和部署能力门禁。真实 importer → loader → stdio → 认证平台路由验证。 |
| 插件中心可显示技能，默认 Agent 注册表却找不到 | 宿主默认发现启用插件技能，按精确名称加载；关闭插件后移除，已有技能冲突时保留原技能。 |
| 导出包缺少完整技能，名称/链接不匹配 | 导出 10 个完整技能与参考；名称带平台前缀，原有前缀不重复添加，README 链接随目录改写。 |
| 真实轨迹只关联数据集元数据，未进入内置 BC | 新增 demonstrationRunId 冻结快照、worker 真实消费与 SHA-256 回执，UI/MCP 使用同一路径。无效来源、跨账号、错契约和超限拒绝。 |
| 录制时动作泄漏进“上一动作”输入槽 | 录制实际 session.run 的推理前输入和同次输出；停止/重录隔离迟到结果。旧版反例 last_action 身份基线 MSE 为零。新 browser 样本必须带 policy-inference-v1 配对标记。 |
| 长遥测在 MCP 摘要/回放时失败或总帧数变成投影长度 | HTTP summary 省去向量并返回精确 sampleCount；回放单独携带总帧数，MCP 披露投影，旧平台总数未知时返回 null。大于 256 KiB 的真实路由反例通过。 |
| 腿式 runtime 没有显式速度命令租约 | 增加 vx/vy/wz 命令，贯通 MCP、平台权限、BoardAgent 和 IPC；限幅、到期归零、停止/故障清零，拒绝模板 profile 与迟到推理。 |
| joint runtime 缺批量零致动推理 | 增加有界 infer_batch，严格校验形状和有限值，返回完整动作；测试中不绑定或发布 ROS。 |

测试先构造修复前失败的反例，再验证修复。Studio 变更位于隔离工作树；既有相机 WIP、
用户插件和真实账号配置未被覆盖。安装在电脑上的 Studio 1.4.4 与修复后的宿主源码是不同验收对象。

## 实测口径

- **原生插件**：本轮 Node 24 验证 58 个完整工具 schema，真实导入、认证 Tool.execute、owner 过滤、默认审批边界；默认 MossApp 发现 10 个技能并通过 load_skill 返回 setup 和 training-runs 的原文，禁用后不再可见。
- **桌面自然语言**：安装版 Studio 1.4.4 发起只读技能/状态验收，模型网关返回 500，未执行插件工具。不能据此声称桌面自然语言 Workshop 已通过，也不能将模型网关失败等同于平台 API 失败。
- **真实软件流程**：真实浏览器 MuJoCo/ONNX、六次 reset 录制、保存、工作台 BC、MCP 调参、来源拒绝和制品哈希由本轮独立账本验证。过程成功与独立闭环策略质量分开裁决。
- **开发板**：仅执行保存连接的恢复与隔离计算，不修改生产 agent、策略、认证或运动开关。最终数值与阻塞项以本轮收据为准。
- **实体**：无机器人本体，未验收。模板关节顺序与 HOME 不能冒充真实标定；循环 ONNX 状态也不能静默忽略。

## 最终学习结果

本轮真实录制 6 段，共 **1611 帧 / 30.38 秒**。修复 MCP 长响应后复用同一份录制，
以新账本导入、训练与评测；报告标记 reused-recording，没有将复用数据说成本轮重新采集。
原始录制 SHA-256 为 `b6bc45a61bbc8aa8ccf517334799e019c9787fbaf262cecf316791701c2210d3`，
训练 canonical JSONL 为 2,205,147 字节，SHA-256 为
`8f8baa230d4ef05b5cc7244076bb3448bba6ac5f2fadff4cdc5aad89f8e914bf`。
100/150 epochs 两次真实 Worker 均核对消费摘要和制品。最终 ONNX SHA-256 为
`3470462e425ef2166312dae629351fadaae0fead629a61bb9a03a12d13daea46`。

**13 个软件执行阶段通过，策略质量未通过。** 最终状态为
`passed-software-training-policy-rejected`；BC 在三种命令回合均被原上游加载器的
constant-output smoke 拒绝，实际 BC 闭环回合数为 **0**，`deployable=false`。
模型在真实录制输入上输出方差 0.001525、MSE 2.066e-5，不能称为全域常量。
近零 smoke 输入偏离 gravity_z 的训练分布约 24,263 个标准差；本轮没有改验证器、
归一化或阈值来让它通过。

独立参考策略站立通过；前进和转向命令已实际进入观测，但跟踪 RMSE 分别约
0.1996 m/s 和 0.4851 rad/s，没有通过该诊断标准。零动作对照三个回合均跌倒。
这些结果不能推导出学出策略可站立、行走，更不能作为实体运动证据。

Studio 宿主修复提交为 `cca1f27a0b76cb4ad124d2bfd37b023331310255`。
其提交后原生功能回归和 harness 通过；完整 fast 为 381/382，唯一失败是新增源码使
冻结审核的旧源码证明失效，未更新或绕过该审核。这不是完整发布门禁全绿。
原安装版 1.4.4 未被替换，原 Studio 相机 WIP 保留。

## 可复现入口

使用满足 package.json engines 的 Node。每次浏览器验收使用独立存储、随机空闲端口和新账本：

```bash
npm test
npm run verify:ui
npm run verify:api-contract
npm run verify:recorder
npm run verify:offline-bc
npm run verify:plugin:contracts
npm run build
npm run verify:plugin
npm run verify:studio-plugin -- --studio-root <修复后的Studio源码>
npm run verify:demonstration-training
npm run verify:board-drive
npm run verify:joint-policy-runtime
npm run verify:board-policy-batch
```

浏览器与 Python 依赖配置见 [示教训练](../demonstration-training.md)。本机原始模型、输入快照、
完整浏览器日志和脱敏计算收据保存在忽略的 dist/testing 下，不把设备地址、凭据或个人路径纳入提交。
固定端口上已有的服务没有停止或复用；本轮没有把 GPU 桥 fixture 或 CUDA 训练计作已通过。

完整发布门禁仍应独立执行；引擎上游锁漂移不是本轮修改锁文件的理由。本轮没有刷新上游锁来消除失败。

## Workshop 放行条件

软件教学应能解释录制、真实数据消费、训练损失与独立闭环质量的区别；未通过的策略保持不可部署。
要宣称完整机器人教学任务通过，还需要：可工作的 Studio 模型通道、学出策略独立闭环合格、
本体关节/限位/HOME 标定、急停与时间盒、相同制品的受控站立/行走和真实遥测回流。
