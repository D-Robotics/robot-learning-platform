# 平台埋点接入 d-obs 可观测系统

## 背景（已查实）

- "同级别项目的可观测系统" = **d-obs**（`/Users/d-robotics/Desktop/超级智能体/d-obs`），生产与平台同机部署（127.0.0.1:18093 vs 平台 127.0.0.1:18102）。平台已作为租户 `sim2real` 接入了每分钟健康拨测，但**事件级埋点通道不存在**。
- d-obs 工作台按 `event_code` 惯例聚合 `studio_ops_events` 表：`http_5xx`、`sso_login_attempt`、`process_unhandled_error`、`tool_call`、`client_error`；「最近事件」列表展示任意 component/event_code。
- 平台侧已有领域事件总线 `registerSim2RealPlugin`（`server/sim2real/sim2real-events.ts`，SSE 路由就是这么挂的）——埋点插件的天然挂点，零侵入 store。
- 用户已确认：**通道 = d-obs 新增事件摄取端点（HTTP + token）**；**范围 = 后端全量第一批**（领域事件 + 5xx + 登录 + 进程错误 + 遥测摄取失败）。

## A. d-obs 仓改动（加事件摄取端点）

### A1. 新文件 `server/monitoring/ops-event-ingest.ts`

`POST /api/ops/events` 的处理器（挂载在 `server/main.ts`，紧跟探针上报路由之后）：

- **鉴权**：复用 `resolveProbeReportIdentity()`（`external-probe-ingest.ts:78`）——平台 token（`x-rdk-external-probe-token`）或租户 token（`x-rdk-tenant-probe-token`）二选一，任一命中即接受，401 fail-closed。身份仅用于日志与 accepted 回执，事件本身按 component 全局落库（`studio_ops_events` 无租户列，与 studio 同为平台级接入）。
- **Payload 契约**：
  ```
  { schema: 'rdk.dobs.ops-events.v1', producedBy: 'sim2real-web',
    events: [ { eventId(uuid,必填,幂等键), component(slug,必填), eventCode(slug,必填),
                outcome('ok'|'error'|'rejected'|'degraded'), severityHint?,
                safeSummary?(≤500), metadata?(≤32键), correlation?(runId/userId/...),
                occurredAt(ISO), dedupeWithinMs? } ] }
  ```
- **上限**：≤64 events/批、≤256KB（超限 413/422，对齐 trace batch 的 cap 风格）；单条字段非法 → 跳过该条计数为 dropped，整批 schema/尺寸问题才整批拒绝。
- **落库**：逐条调 `recordOpsEvent({ ...input, fingerprintParts: [eventId] })`（`ops-event-store.ts:267`）——消毒/去重/建表全部复用现成逻辑；`eventId` 进指纹 = 客户端重试天然幂等。
- **响应**：`202 { ok, accepted, dropped, tenant }`。

### A2. 测试 `server/monitoring/ops-event-ingest.test.ts`

仿 `external-probe-ingest.test.ts`：无 token 401、错 token 401、坏 schema 400、超 cap 413、单条字段坏→dropped、重复 eventId 幂等（只落一行）、租户/平台 token 都可用。跑法：`node --import tsx --test server/monitoring/ops-event-ingest.test.ts` + `npm run typecheck`。

### A3. 文档

新建 `docs/event-ingest.md`（契约 + curl 示例），`docs/tenant-onboarding.md` 末尾交叉引用一句"事件级埋点见 event-ingest.md"。

## B. 平台仓改动（埋点采集与上报）

### B1. 新文件 `server/sim2real/dobs-ops-reporter.ts`（核心，零新依赖）

`createDobsOpsReporter({ url, tokenFile, enabled })` → `{ reportEvent(input), plugin, metricsViews, dispose }`：

- **队列**：内存 FIFO，上限 1000 条，溢出丢最旧并计数；满 8 条或每 5 秒批量单飞 POST（≤64 条/批），6 秒超时。
- **重试**：失败退避 5s→30s→120s，连续 5 次失败丢批（防无限增长），错误走 `redactInternalError` 打 stderr——与插件总线"绝不影响主链路"的约定一致。
- **token 轮换**：401 时重读 token 文件（64-hex，仿 `board-telemetry-uploader.py` 的 token 处理）。
- **领域事件映射**（作为 `Sim2RealPlugin`，id `dobs-ops-reporter`，事件集 = SSE 的 CLAIM_EVENTS 去掉 `telemetry.appended` 防噪音）：
  | 领域事件 | event_code | outcome |
  |---|---|---|
  | run.created | `run_created` | ok |
  | run.updated | `run_status_changed` | status=failed→error，否则 ok |
  | deployment.created/updated | `deployment_created`/`deployment_status_changed` | 同上 |
  | model.created | `model_registered` | ok |
  | project.*/dataset.*/evaluation.* | `project_created` 等 | ok |
  - metadata 只放低敏字段（engine、status、taskPack 名），correlation 放 `{ runId, userId: owner }`，`event.id` 作为 eventId。
- **env 配置**（默认未配置即整体停用，本地开发/CI 零影响）：`RDK_SIM2REAL_DOBS_URL`、`RDK_SIM2REAL_DOBS_TOKEN_FILE`、`RDK_SIM2REAL_DOBS_REPORT_ENABLED=0` 作为 kill switch。

### B2. 挂点接线（`services/sim2real-web/server.ts`）

- 在 SSE 路由注册旁（`server.ts:796` 附近）实例化 reporter 并 `registerSim2RealPlugin`。
- **5xx 埋点**：`server/sim2real/observability.ts:356` 的中间件 `response.on('finish')` 里 `status>=500` 分支，通过新增可选回调 `onServerError({ route, status, requestId })` 通知 reporter——observability.ts 保持"零传输"纯度，传输归 reporter。emit `http_5xx`（outcome=error，metadata 带 route/status）。
- **登录埋点**：`server/sim2real/studio-login-relay.ts`（POST /api/sso/login）成功/失败路径 emit `sso_login_attempt`（outcome=ok/rejected/error，不记任何凭证字段）。
- **进程错误埋点**：`server.ts` 启动时注册 `uncaughtException`/`unhandledRejection`（现状：没有），emit `process_unhandled_error` 后维持原有退出行为。
- **遥测摄取失败埋点**：`server/routes/sim2real-telemetry-routes.ts` 的 `appendSim2RealTelemetryWithResult` 失败分支 emit `telemetry_ingest_failed`（补 `docs/real-loop-validation-2026-09-14.md:306` 点名的缺口）。
- **自观测**：`observability.ts` 加两个指标（沿用基数上限约定）：`sim2real_dobs_events_total{outcome}`、`sim2real_dobs_queue_size`；`/healthz` 载荷加一行 reporter 状态（队列水位/最近失败时间）。

### B3. 测试与文档（平台侧）

- `server/sim2real/dobs-ops-reporter.test.ts`（vitest）：映射（run failed→error）、队列上限丢旧、退避重试、kill switch、未配置默认停用、回调永不抛。
- `.env.example` 加三个 env；`docs/operations.md` 新增"d-obs 事件埋点"节（env 表、event_code 表、kill switch、验证方法）。

3. **部署**：d-obs 按 `docs/deploy.md` 流程发版（build:clean→tar→scp→切软链→restart）；平台 token 取 `RDK_TENANT_REGISTRATION_TOKEN` 注册专用租户（或复用 `/var/lib/d-obs/probes/sim2real.token`，按 service 读权限定），env 写入 standalone-sim2real.service 后重启。
