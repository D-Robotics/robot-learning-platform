# 场景准备与恢复

用户说“开始体验”“帮我准备演示环境”“课程自检”“恢复仿真”时使用。流程由目标和配置决定，允许跳过已完成步骤、回答原理、自由探索，随后回到原步骤；不要强迫用户按固定话术操作。不要默认进入课程模式。其他工作区、训练、部署工具继续照常使用。

配置示例见 [体验配置](../../references/experience-profile.json)。复制后可换名称、必需工具、参考策略或固定 Run；训练策略须同时填 policy.runId 和 policy.sha256，不自动挑最新模型。组织者可以附 trainingTemplate；读取模板不代表获准提交训练。不要把个人 Run、凭据、地址写进共享配置。

## 准备

沿 [平台连接技能](../setup/SKILL.md) 复用当前宿主的同一 MCP 连接与身份。依次调用 rdk_platform_status、rdk_simulator_open；检查工具目录、平台 ready、降级状态和账号。当前连接未就绪时报告具体阻塞，不创建匿名实例或改账号。

仅参考体验遇到 `SIM2REAL_API_NOT_FOUND` 且 HTTP 404 时，可调用同一连接的 `rdk_workspace_overview`，使用其 `integrations.simulator` 入口，记录兼容分支；不得自行猜地址。401、403、超时和训练策略入口失败不走此分支。

有可用终端且确认脚本绑定与当前宿主连接一致时，也可调用随包 scripts/experience.mjs：

```
node <插件目录>/scripts/experience.mjs check <配置文件>
node <插件目录>/scripts/experience.mjs prepare <配置文件>
node <插件目录>/scripts/experience.mjs recover <配置文件>
```

脚本仅实时调用现有 MCP 只读工具，不安装依赖、不启动平台、不写台账；输出准备状态、入口和待执行步骤。exit 2 表示阻塞或仍需验证。插件版本由宿主安装管理，发现缺工具时提示核对兼容版本。相对入口保留配置平台的挂载前缀；拒绝跨 origin 导航。

## 执行与确认

通过宿主已有浏览器能力打开入口。浏览器能力缺失时返回可点击链接及具体操作，不声称已打开。使用实际页面控件选择场景与策略；界面有差异先观察，不猜选择器，不注入未经支持的控制接口。

在 Studio 中，宿主工具目录提供 `studio_open_url` 时优先用它打开页面；需要核对内嵌页时优先使用目录中实际可用的 `studio_embedded_browser_capture`。打开回执、页面可见、引擎就绪和运动成功分别记录。不要为了确认内嵌网页而默认调用系统级 `computer_window_list`、桌面截图或点击工具，也不要要求额外的屏幕录制和辅助功能权限。内嵌页采集不可用或失败时，保留实际错误并交给用户观察页面；返回地址或宿主接受请求都不等于已经看见页面。

安装说明须匹配当前宿主实际入口。已验证的 Studio 目录导入路径是下载插件 ZIP、解压、在“AI 能力 → 扩展中心 → 添加 → 从目录导入插件”中选择含描述文件的解压目录。不要把 ZIP 地址或独立 HTTPS marketplace JSON 当作所有版本 Studio 都支持的“公开源仓库”；目录导入完成后仍按 setup 技能核对账号连接。已有连接不因重新导入就自动失效，也不能据插件卡片存在宣称 MCP 已连通。

参考策略明确标记为参考体验。训练策略先调用 rdk_training_status 核对指定 Run completed，继续通过 rdk_artifacts_list、rdk_lineage_get 及平台真实制品接口核对来源、保留状态、SHA 和独立评测。当前工具投影缺失证据时保持待验证，不把 completed 或训练指标当作质量合格，不自动退回参考策略冒充指定模型。

先等待引擎与控制器加载完成；初始几秒的低控制频率不算就绪。页面稳定后再下达移动指令，松开按键并观察速度回零。在页面看到加载成功后才报告策略已加载；实际观察鸭子运动、停止后才报告对应成功。记录本次入口、配置 ID、策略来源、完成步骤和下一步。页面未给加载来源或运动证据时报告未验证。详见 [平台连接技能](../setup/SKILL.md)。

## 训练、调优与整体检查

扩展入口可用时，先用 `rdk_workflow_inspect` 返回一张流程状态表；传明确的 Run、资源、评测 ID，不把全局摘要或其他 Run 的结果当成本次完成证据。按阻塞项继续，不展开与目标无关的大量查询。

新训练提交前使用 `rdk_training_prepare`，刷新所选资源的健康状态，再检查任务环境；单独环境预检通过不代表资源健康记录仍有效。续训还需确认原 checkpoint 确实保留在所选 Worker 上，不因另一台 Worker 在线就自动换资源。保留幂等键，已提交的任务只查询原 Run。

短续训用于体验真实采样、参数生效和导出链路；不能称为从零训练。一次只改少量参数，核对实际执行指标，再对同条件独立评测进行比较。误差增大或质量退化时如实说明，默认保留原版本；不强求调参必然提升。

用户选择“参考策略走主线、训练结果作对比”时，保留这个选择：不按最新 Run 自动替换主线，也不把训练完成当作升级批准。若目标包含站稳或停止，分别检查零指令、持续移动、移动后松键；恒速行走评测通过不能证明停稳。对比结束后确认页面已恢复参考策略，不把试跑自动恢复后的静止归因于训练模型。

MCP 登录与网页登录分别验证。网页显示游客时，自训模型加载和保存仍受阻，应在页面正常登录同一账号；不复制会话 Cookie。桌面内仍返回 `STUDIO_COMPUTE_HOST_REQUIRED` 时，报告宿主接口未接通，核对兼容性；不能继续声称“用户尚未在桌面执行”，也不伪造宿主令牌。部署预检拒绝时保留具体原因，不改制品标志或跳过板卡探测。

## 录制与回放

先区分入口：画面内“动作录制”输出 microduck-trajectory-v1，用于分析或后续模仿学习；新录制需核对 pairing: policy-inference-v1，确认输入输出来自同一次推理。工作台外层“录制状态”输出 microduck-state-snapshots-v1，用于诊断，previousAction 不能当作对齐训练标签。两种 JSONL 不混用。

完整状态按“录制状态 → 停止录制 → 保存录制 → 查看录制”操作，检查帧数读取、播放推进和末帧停止。当前状态向量播放器通过，不代表三维姿态重演或真机视频通过。没有宿主页面控制能力时引导人工操作，不声称 MCP 已点击按钮；保存文件也不等于创建 dataset 或获得评测证据。

## 恢复与后续

恢复前停止当前仿真；有未保存录制时先询问保存或放弃。使用页面恢复初始场景，再加载原配置策略并观察结果。恢复只作用于当前仿真，不删除训练、不重置板端、不停止其他用户任务。失败后给明确原因与下一步；不循环重试，不重复提交训练。

对训练进度继续查原 Run；耗时较长时可由用户选择加载事先指定的合格模型继续，并记录策略来源变化。趣味挑战使用当前已验证场景，成功条件以实际观察为准。真实硬件、视觉跟随和量化部署需要各自能力与证据，不能从仿真成功推断。
