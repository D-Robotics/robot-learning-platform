# 新机器人接入验收

新学员首次接入、说“不知道怎么开始”或资料未齐时，先使用 [classroom-rehearsal](../classroom-rehearsal/SKILL.md)：调用 `rdk_classroom_guide` 携带上下文已知answers，每次只引导一个中文问题。默认只显示studentReply，不读全套资料、不让学员填五个技术摘要。

准备信息齐、确实需要阶段标准/模板时才调用 `rdk_robot_onboarding_guide`（默认简短）。只有具体接口争议或用户要求依据时才传detail=full；不重复读取工具已返回的参考内容。技术证据用 `rdk_robot_acceptance_assess` 检查，并传入本轮已知answers以免重问称呼或模型状态，needs-input是未通过的准备状态，按中文missingInputs补齐，不能为了通过伪造身份或摘要。

当前目标设备有歧义先辨认；使用插件当前账号的设备记录和真实工具目录，不扫描账号、猜密码或假设通用策略启动支持所有机器人。连接与板端工具使用 [devices-board](../devices-board/SKILL.md)。

把每台机器的身份、适配器、标定、模型、运行时摘要写进项目私有记录，按阶段引用原始收据；调用 `rdk_robot_acceptance_assess({record})` 检查覆盖、绑定与期限，展示已证明、未知、阻塞和下一步。它不保存记录、不核验原始文件、不能替代平台运动门禁。缺证据不填 true，不把工具的 ok 当成设备通过。

优先离线准备，需上电才提示现场配合，避免让机器人承重等待软件修改。只读诊断也先确认所用SDK导入/查询是否会初始化串口或启动动作。完整循环测量延迟和时效，负状态不填零，过期队列不接受。通信连续失败或温度异常时停止实体试验并保留证据，修复后重新生成相关阶段证据；不能通过延长超时、取消热保护、盲目重启清除阻塞。

实体试验需要已实现的机型适配器、平台与板端门禁、当前现场条件和用户动作授权。Qoder/MCP 只编排；实时控制在板端。没有执行适配器就交付未接入项，不经 SSH 绕过门禁。不要为了文档验收驱动机器人。

结果分别说明数值一致性、影子运行、静止、抗扰对照、长期热/通信稳定性。历史静止通过不转成新机器人资格，策略参与控制不证明RL优于传统反馈。只在当前已授权目标内继续，未知的物理动作结果不自动重试。
