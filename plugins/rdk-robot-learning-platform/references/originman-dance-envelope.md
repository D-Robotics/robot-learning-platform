# OriginMan 舞蹈幅度与有效限幅

用于“腿不明显”“放慢并加大幅度”“原厂能蹲，RL 为什么只动几度”以及舞蹈版本交付。
沿用 [实体接入边界](originman-onboarding.md)，本页不新增运动工具或解除保护。

## 先报告限制来自哪里

逐轴核对以下层级，记录源码版本、模型摘要和本机标定来源：

1. 原厂协议单位、装机机械范围、逐机零偏与站姿；舵机 pulse 回中值不自动等于模型机械角度零点。
2. 训练动作 scale、参考动作与奖励；说明模型直接输出目标还是只输出编排残差。
3. 导出后投影、clip、足底约束、变化率与关节耦合。
4. 运行器逐轴相对计数限幅、起点容差与回位容差。
5. 板端写入接口绝对计数窗口、持续时间和串口所有者。

有效范围取所有层级交集。相对目标必须先转为绝对目标：
`targetCount = commandHomeCount + round(sign * targetAngle / anglePerCount)`。
固定已确认的指令站姿与观测参考，分别记录。承重回读偏差不是编码器零偏；不要每次把实测起点重新写成指令中位，避免累积漂移。
再核对写入接口的绝对窗口；起点偏差会消耗一侧的可用幅度，不能只比较相对偏移。
角度换算必须有来源，不能默认所有舵机、机型都是同一每格角度。

报告至少包含：关节/轴、起点回读、各层计数窗口、角度换算来源、最终可用正负角度、实际峰值与全程范围、收尾静止指标、限制来源、缺失证据。
无法读取某层时标记未知，不宣称幅度已放开。

## 如何扩大动作

- 固定用户指定的 BPM、拍数、承重方式和是否有外力。用户要求无侧推时不添加侧推训练或实体推碰。
- 原厂动作文件只读解析可帮助识别候选姿态；其中的极值不等于当前样机已验证的机械安全范围，也不授权执行整个动作文件。
- 临时小幅工程窗口不是机型极限。具体实验出现过站姿附近 ±18 格的板端窗口和膝部 ±8 格的运行器窗口，不能把它们当作通用默认值或写入新机配置。
- 需要扩大窗口时，在独立候选配置中按逐轴标定、安装空间、原厂候选姿态、传动方向和实际跟随能力确定范围；保留原版本。更改模型、投影、运行器或写入窗口后，必须在相同有效配置下重新评测，不能只增加输出倍率。
- 用户已授权的下一步正常推进；已有现场确认在条件未变化时沿用。动作故障后按现有停止/重新确认纪律处理。

## 训练与验收证据

编排可作为奖励参考。若宣称“PPO 直接驱动”，部署目标必须来自 actor 输出，经已声明的限幅/足底投影得到；不能在实体短试中用固定屈膝脚本替换 actor 后称 RL 闭环通过。若使用规则与 PPO 残差组合，明确两者贡献。

在匹配模型、BPM、延迟、限幅和机械配置下比较规则与 PPO，记录训练耗时、采样步数、输入/输出、模型 SHA-256。训练完成或 actor 有非零输出不等于舞蹈达标、RL 优于规则或真机有效。

把完成、安全与表现分别报告：

- 完成：实际完整 8 拍、无故障、是否发生降级、是否通过结束回位。
- 安全：双脚接触、非脚底/踝壳触地、倾角、跟随误差、反馈年龄和保护触发。
- 表现：每膝峰值角度及变化范围、左右换重心位移范围、头部/手臂行程、节拍与定格。收尾阶段平均膝角不能代表舞段峰值。

已有大动作质量评分失败时保留该结果；不能因为另一个小幅安全门通过，就把总体质量改成通过。新增幅度档应给出相对旧版的实测增量，并明确是否达到用户要求的幅度。

掉帧时冻结舞蹈相位，补读恢复新鲜度、响应身份与稳定姿态后从原拍继续；保留硬保护，不用插值或上一帧冒充真实回读。更改等待时间应核对 SDK 查询、迟到帧隔离、IPC、RPC 回复等待和整段墙钟预算，避免外层允许补读而内层先锁死。记录未恢复故障帧的倾角、角速度、数据年龄和停在哪一拍，避免只留下通用错误文本。

## 部署状态与重启

区分差分目录和完整执行包；报错应定位调用与具体路径，不能仅凭 `Errno 2` 判断缺少模型。确认模型、配置、模块及服务套接字的实际存在性。
临时目录下的服务覆盖配置重启可能丢失；持久配置写入不等于重启恢复已验证。保存现有服务状态与回滚配置，服务启动可能执行原厂站姿，不能当作零致动检查。

插件知识更新只改进 Agent 操作流程。只有执行适配器及真机报告证明新范围生效，才报告“限幅已解决”；不得把文档更新说成驱动能力已实现。

## 有界容错与可见效果

- 静止小偏差须由多次不同时间戳的新鲜回读证明稳定；确认范围内才继续，不能以单帧或平均值掩盖持续跟随误差。
- 对无请求序号的串口协议，重试的旧包与新包可能混淆。恢复探测仅查询位置，隔离窗口内的回包全部丢弃，不能发布为新观测；恢复后再获取真实回读。补查次数、隔离时间、总暂停时长均有上限。持续无回包、无效状态或错误身份仍停机，不能清空保护标志后继续写动作。
- 区分运动命令的回复超时与串口读失败。回复丢失不代表命令未执行，禁止自动重复动作写入；保留命令审计与实际位置。适当延长回复等待不会消除持续通信故障。
- 软件判定“跑完”之外，要求可见幅度证据：用连续多次新鲜回读计算实际行程，单帧尖峰不计。头部 PWM 指令回显不得冒充头部实际角度。
- 上身版、减幅版、带腿版分别验收。一次上身成功不能证明腿部闭环通过；不能宣称已证明 RL 优于规则。开始前倒数，可重复短舞段，每轮回位验证失败就停止后续轮次。
