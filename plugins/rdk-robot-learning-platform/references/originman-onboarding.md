# OriginMan 新机接入与有限实机验证

用于“新机器人接上了”“继续之前的站立模型”“核对标定”“仿真有效，真机怎么验证”。先明确本次是只读接入、软件回放还是已授权的实体试验。训练工作台的仿真能力不代表当前平台已有 OriginMan 实体执行适配器。

## 选择当前能交付的阶段

按实际工具目录和板端能力选择入口。平台设备预检、策略暂存、加载与运动各自保留门禁；没有 OriginMan 实体适配器就明确该阶段未接入，不能把通用策略启动当作兼容接口。手动 SSH 联调不能绕过平台阻断或改写制品硬件资格。已有经明确授权的独立工程试验，应单独记录执行路径和有限范围，不回填成平台部署通过。

插件提供下面的知识流程与[脱敏案例摘要](originman-standing-evidence.json)，没有新增自动标定、实时运动或一键实体验收工具。仓库存在 `docs/originman-standing-trial.md` 和 `services/sim2real-web/originman_runtime.py` 时，再核对其当前实现、依赖与接口；便携知识包不携带该试验运行时或模型。缺执行环境时先交付检查结果与阻塞项，不编造工具或临时脚本冒充已验证入口。

## 新机器的顺序与阶段证据

| 阶段 | 核对内容 | 完成证据与停止条件 |
| --- | --- | --- |
| 找回连接 | 当前账号保存记录、真实设备身份、SSH认证、系统与Python ABI | 一次实际只读响应。历史connected不代表现在在线；认证失败先找回用户已提供的信息，不猜口令 |
| 固定制品 | 训练来源、原模型、归一化、参考轨迹、源码与SHA-256 | 同名seed文件可能不同；维度相同不代表动作语义相同 |
| 只读硬件盘点 | SDK版本、串口全部持有者、官方站姿、本机零偏/位置/寄存器限位、电压温度 | 不执行站姿文件读取参数，不import会创建Board或发动作的模块 |
| 样机标定 | 关节身份/正方向、中心、安装轴向、IMU单位和偏置 | 官方资料优先，只对无法确定的方向做现场小幅核对。寄存器限位不能替代机械限位 |
| 隔离推理 | 独立依赖环境、原字节模型、已知输入/参考输出 | 主机与板端数值误差及摘要；纯推理不等于运动成功 |
| 实时零致动 | 完整真实观测、全链路延迟、数据年龄、失败处理、原进程恢复 | 单读者、真实采样和实际运行时；不能只跑一个空定时器证明控制频率 |
| 有限实体试验 | 同配置仿真、源码绑定、急停/看门狗、当前现场状态 | 已有实体授权、有人防跌且能断电。短试成功并确认现场结果后再延长；异常停止后续动作 |
| 对照与结论 | 同一限制下的传统反馈与RL、关节回读、实际发送、现场观察 | 静止、抗扰和长期运行分别评价；手动推碰不是已知牛顿力，未测的不报告通过 |

连接与凭据留在宿主安全配置，设备地址、账号口令、个人路径不进入共享报告或插件。依赖安装使用独立环境，不升级官方系统环境来满足探针。

插件宿主的Node与板端Python分别检查。Node已经安装不代表满足当前项目engines；使用包内安装器或已核对的兼容运行时，不全局替换默认Node。依赖存在也不代表版本匹配，按锁文件与实际包版本验证。

先自动收集能从保存记录、官方资料、安装源码和只读回包确定的内容，将确实需要人的现场姿态、关节身份与方向集中提问。已有授权范围内继续软件与只读工作，不重复索取同一许可；软件检查间隔较长或异常停止后，重新确认当前现场状态。方向未知时保留未知，不为了减少提问猜测方向或跳过标定。

## 先复用官方资料，再核对每台安装

- [动作编辑器](https://originman.guyuehome.com/zh/manual/action_editor/)提供编号、微调和回读；[基础程序](https://originman.guyuehome.com/zh/application/basic_program/)给出IMU示例；[协议说明](https://originman.guyuehome.com/zh/manual/protocol_description/)用于核对通信。查不到时可用官网MkDocs的 `search/search_index.json` 精确定位，不把搜索无命中当作没有资料。
- 只读提取官方 `stand.d6a` / `stand_slow.d6a`，以及动作编辑器的读取/保存零偏逻辑。某些镜像的 `CalibrationConfig.py` 是相机标定，不能按文件名推断为关节标定。
- 固件已保存零偏时不要再叠加一次。设备寄存器范围、名义计数角度比例和实测机械限位分开记录。案例的关节ID、中心、符号和IMU变换都不能复制成另一台机器的标定。
- IMU示例为g和deg/s；策略需要安装轴变换、姿态、弧度制角速度以及实测关节速度。状态不完整时不能用零填补。
- 校准小动作看不清时先确认关节可自由转动、脚掌没有承重或被手限制；不得只增大幅度掩盖跟踪偏差。每次异常都先确认现场，失败动作不自动重试。

## 从失败中保留的运行时约束

1. **按完整控制链选择频率。** 案例中的50Hz原型出现推理后目标过期、混合轮次读数过期，以及连续固件读取失败。最终25Hz是这次重新仿真与实测过的工程设置，不证明硬件不支持50Hz，也不是新机器的默认答案。训练频率与执行频率分别记录，改频率、限幅、变化率或估计器后重新评测。不能把仿真manifest的50Hz直接改成25Hz来掩盖差异。
2. **不让通信等待消耗状态时效。** 已验证方案在控制槽内完整读取四关节，再取状态、推理与发送。原先后台轮询的平均耗时很低，仍可能在控制边界留下部分更新的快照。位置和IMU保留真实接收时间；接收年龄也不能冒充传感器真实采样年龄。
3. **失败值不变成位置。** 状态-1不是位置0。案例允许整个周期不发目标，下个计划周期重新完整读取；最多一个连续未发送周期，总预算为计划周期数的2%向下取整、至少1个，与过期提案共享预算。未发送不推进上次动作。该规则先经过丢指令仿真，不能泛化为忽略超时、CRC、非法回包或不确定写入。长测仍有孤立失败，不能写成通信已根治。
4. **恢复过程同样验收。** 不重启可能执行站姿/鞠躬的官方服务。核对PID和启动身份后暂停，恢复原串口配置并继续同身份原进程；独立看门狗恢复失联试验进程，恢复期间继续持有互斥锁。Linux用自有进程与PTY实测恢复路径，mock通过不足以替代。
5. **所有“通过”绑定实际字节。** 同名权重、不同源码、不同频率的报告不能共用许可。归一化epsilon=0可以合法，条件是每项variance+epsilon均为正；不要为了适配加载器改模型参数。阶段名称也不证明源版本，暂存或元数据写入失败后核对实际摘要再继续。
6. **正常结束和故障结束分开。** 正常结束可按已验证的变化率返回中心并回读；故障时不凭未知状态自动执行回位轨迹。UART接受字节只证明写入，需结合关节回读；IMU平稳仍需现场确认双脚着地、无人扶持。
7. **低频诊断也要维持租约心跳。** 一秒一次的温度采样不能直接睡一秒：等待期间在调用线程内分段检查取消并发送心跳。不要用独立线程替失去响应的采样循环持续报活。高频样本用JSONL组织并有界缓冲，避免每帧重写不断增长的报告或每行同步刷盘拖慢采样；强制杀进程可能丢失尚未刷盘的缓冲，另留独立恢复收据。核对实际频率与总时限，初始化报告或残留日志不算通过。信号取消不能直接标成操作者主动停止。
8. **温度与供电单独留证。** 在当前机器核对温度、电压寄存器协议，保存开始、趋势和结束读数。读取失败保留关节ID、命令、状态和原始回包，不能当温度零。寄存器保护上限不等于适合本次试验的起始温度；研究诊断的保守温度门限应明确标为工程设置。分别记录承重与不承重、充电与纯电池，不把一次短时改善认定为根因或长期修复。不承重稳定也不能替代承重检查；关节位置接近官方目标不证明不存在持续负载或机械受限。
9. **官方接口和实时约束分别核对。** 查当前官方完整协议及已安装SDK，记录读取状态、阻塞/重读行为、频率约束是否明确。配置写入后的延时不等于读取最小间隔；波特率不等于查询吞吐。官方封装的多次失败重读不能原样搬进实时控制。必要时以摘要固定的官方SDK原API做只读对照，列明额外的有限等待与写白名单；队列已有数据也要检查接收时刻是否超过请求期限。仓库有 `docs/originman-interface-contract.md` 时按其中方法复核，保留未查明项。上电前完成代码和提示流程准备，避免让机器人承重等待长时间软件工作。

## 记录本机配置，避免下次重新猜

保留每台机器的设备身份、镜像/SDK、官方站姿摘要、关节映射与方向的证据、本机零偏、机械限位状态、IMU变换/单位/偏置、模型与归一化摘要、训练与执行频率、限幅/变化率、采样与失效策略、验证报告摘要。该清单是记录约定，不是一个已经实现的注册API或自动标定schema。

旧策略案例参数与数值见[案例摘要](originman-standing-evidence.json)；后续新候选的影子/3秒静止与未解决故障见[新候选摘要](originman-candidate-evidence.json)。两份记录对应不同模型，不可混用。它只证明一次有限静止试验；模型原有 `hardwareEligible=false` 未改变。下一阶段应是现场授权下可记录的小幅左右扰动对照，再考虑更长运行。没有这些证据时，不推断RL抗扰更强或已经可生产部署。
