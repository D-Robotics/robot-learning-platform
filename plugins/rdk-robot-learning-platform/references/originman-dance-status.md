# OriginMan 舞蹈训练插件状态

截至 2026-11-09，本工作树新增了独立的 `originman-dance-ppo` 训练适配器、78→18 模型契约、受限编舞配置、训练规格透传、Worker 引擎健康回报，以及插件工具 `rdk_originman_dance_train`。该入口和原有 `rdk_workshop` 受扰恢复课程分开；舞蹈训练使用 PPO、自定义 BPM/舞段和独立模型注册，不复用恢复课程的 SAC、14→2 合同或 push 参数。

## 已有代码证据

- Worker 适配器遵循平台的 request/result 文件协议，可由自定义 Worker 引擎路由启动；要求外部挂载完整 OriginMan MuJoCo bundle，并校验 20 个关节、21 个网格 SHA 和有限参考轨迹。
- 学员编舞限 1–8 段，每段为 4/8/16 拍，BPM 为 80–140，强度为 0.25–1，总长不超过 128 拍；策略观测固定 78 维，动作输出 18 维。
- 新舞蹈训练默认 50 万训练步、8 个并行环境；8192 步仅用于学员明确选择的链路快检。API 会把省略预算规范为 50 万步并保存在 Run 输入中，避免依赖 Worker 的隐式默认值。
- 插件训练入口校验独立模型 manifest、当前账号模型与资源、Worker 声明的 `originman-dance-ppo` 引擎能力，随后以稳定幂等键提交 Run。资源未报告真实连接、非 Mock Worker 或目标引擎时停止，不换用恢复任务。
- 本机挂载的模型包上，一次 8192 步 CPU MuJoCo 流程成功生成 ONNX 策略和舞蹈轨迹回放。机器人完整跑到编舞终点且未摔倒，但交替摆臂、换重心、下蹲起身和展开定格均未通过风格质量门，`qualityGate.passed=false`；这只是原型证据，不是学员效果基线。
- 已通过已安装插件的 MCP 启动配置完成真实账号下的模型登记、资源检查、平台训练提交、GPU Worker 执行、ONNX 留存和结果查询。两轮低幅摆臂实验均完成 501,760 步，质量门均未通过；第二轮奖励相位修正也没有形成效果提升证据。
- v2 观测契约新增显式左右换拍相位。随后隔离实验与插件平台复跑均完成 501,760 步，100 BPM、8 拍、强度 0.25、seed 7 的单段交替摆臂在 95/100/105 BPM 全部通过原有幅度、交替比例、节拍与无摔倒质量门。该证据仅覆盖这组简单舞段，不覆盖其他种子、复杂编舞或真机效果。v1 模型仍选择 v1 观测，不能混用策略输入。
- 训练引擎可调用 `render_replay.py`，把本次 NPZ 仿真轨迹渲染为 MP4，并绑定场景、轨迹和策略摘要。缓存 0.6.14 附带的历史记录称真实平台曾生成并播放 4.82 秒视频；但当前公开工作树没有实现 `GET /api/v1/duck/runs/:id/dance-video` 媒体路由，不能把该历史记录当作当前分支可播放证明。插件只透传平台明确返回、同源且绑定本 Run 的 `links.danceVideo`，不自行拼造媒体地址；没有链接时保留训练和质量结果，不为补回放重训。
- `compute_probe.py` 只加载 ONNX 并对比同字节策略与归档仿真观测，不导入串口、ROS 或机器人控制模块。开发机侧已验证 16 组 78→18 输入输出；板端比对尚未完成，不能据此声称部署通过。

## 仍未达到的验收

代码仓库的插件测试不能证明某台 Qoder 的既有对话已刷新到新包。本轮已验证从插件启动配置到平台训练 API、Worker、制品与台账的真实 Run；另已在 Qoder 桌面确认插件安装启用，并用新的自然语言对话通过插件只读查询真实舞蹈 Run、源核验与质量门。0.6.13 原生自然语言训练也已真实完成同组 501,760 步并通过三档质量门；原生调用曾绕入错误字段、旧模型记录和恢复课实验页，因此后续版补充准确参数与舞蹈回放分支。不能把本轮外部浏览器播放证明替代 Qoder 自动播放验收。

本机 bundle 的 21 个网格哈希与 manifest 一致，但 `scene.xml` SHA 与 `sourceSceneSha256` 不同。两者含义不同：sceneSha256 要精确绑定 Worker 实际加载的场景，sourceSceneSha256 保留上游场景来源；新版本要求第一个摘要存在且匹配，并在结果中单独记录第二项是否一致。素材仍不打入便携插件，外部 OriginMan 模型包的再分发授权未核实。

`rdk_originman_dance_train` 只负责提交训练；提交后需对原 Run 调用 `rdk_training_wait` 和 `rdk_training_status`。Worker 当前在该 Run 内做三种 BPM 的仿真检查，风格质量失败必须如实显示。简单单段 v2 摆臂已有上述通过证据；独立评测 Run 与复杂编舞质量仍未验收。本提交新增按 Run ID 读取的只读训练详情页，并通过合成 fixture 验证；尚未用生产账号验收本页面，也未在本分支实现舞蹈 MP4 媒体读取路由。

当前模型输出 18 个动作，两个头部执行器未进入策略。关节零位、方向、限位、动作时序、策略一致性、急停和现场防护均未验收。因此插件不提供 OriginMan 舞蹈的部署、策略启动或电机动作入口，不能声称真实机器人已经会跳舞。
