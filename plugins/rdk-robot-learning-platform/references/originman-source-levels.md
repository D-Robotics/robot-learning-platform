# 哪些公开已有，哪些是我们发现的

下表资产路径指独立的 OriginMan资料包_20261105.zip；插件只携带本说明和案例摘要，不包含表中所有源文件。

“我们”指本项目中的代码审查、仿真、真实采样与现场操作者共同提供的证据，不表示发现了厂商未披露的通用硬件缺陷。

|内容|来源性质|本包位置/结论边界|
|---|---|---|
|协议帧、命令码、位置/电压/温度读取状态|官方公开已有|官方协议（原始PDF在独立资料包中）；状态0成功、-1失败，但内部失败原因未公开说明|
|官方SDK读取实现、Controller封装|公开已有；重试语义是我们审查提炼|sdk-new.py、official-controller.py；None后10ms再读，默认50是计数限制，不是50秒的实时期限；导入副作用需核对|
|关节编号、动作编辑、原厂站姿/动作组|官方资料已有|历史硬件参考；不能代替逐机方向/零偏/机械限位核验|
|最大查询频率/最小读间隔|本次资料未找到明确规定|不能写成“厂家保证25/50Hz”；四关节25Hz是100次位置查询/秒，温度电压另计|
|原URDF与网格|用户提供/历史留存|02_模型与仿真资产；不能把未核实的公开授权标成官方开源许可|
|MuJoCo适配、训练、残差策略、工程运行时|我们改造/编写|项目仿真假设与工程限制须单列，模型惯量/碰撞近似不等于实测标定|
|关节实际身份与方向、IMU安装变换|本样机现场核验/工程估计|样机结论，不能套给新机器人；仍有机械范围等未完整验收项|
|50Hz时序失败、25Hz受限方案有限通过|我们测得的本配置现象|全链路时序决定当前可用性；不是硬件统一频率上限|
|低频诊断心跳被长等待耗尽|我们复现并修复的软件问题|调用线程分段心跳/取消检查，不用后台心跳掩盖卡死|
|全量报告重写/逐行刷盘拖慢采样|我们复现并修复的软件问题|有界JSONL缓冲；强杀可能丢未刷盘数据，初始化报告不算完成|
|队列已有回包绕过截止时间检查|我们用位置和测温反例复现并修复|出队后仍核对真实接收时间；这不解释固件为何返回-1|
|官方SDK短时1/10/25Hz每关节查询均正常|我们真实对照测得|每档仅6秒，后续官方SDK仍出现负状态，不能宣称根治|
|旧策略30秒、新候选3秒自行静止站立|我们日志＋操作者确认|分别对应不同权重和源码；不等于抗扰/长期/新机器资格|
|目标不同于零学习残差的一步回放|我们从实际轨迹重放计算|说明学习残差参与目标；不是闭环对照优势|
|持续升温、间歇负状态、一次全链路无字节|我们观测到的问题|根因未确认，不能仅因降频/换电池/重启后改善就判为硬件或软件根治|
