# 课堂如何让Qoder少犯错

建议用少量明确的入口技能，配分主题知识，不把每次故障都变成彼此冲突的独立技能。

1. 接入：官方资料/已安装SDK审查、当前设备身份、单I/O所有者、供电温度、逐机标定。
2. 推理：固定原模型与归一化、主机/板端数值一致、真实传感器全周期影子。
3. 诊断：负状态与无字节分开；超时和过期不填零；热趋势、承重与供电对照；软件反例修复后再验证。
4. 实验：传统反馈和RL在相同限制下比较，保留失败，训练成功与策略变好分别报告。
5. 交接：同一设备/模型/代码绑定的阶段证据；任何未知保留未知。

课堂提示词：

> 接入这台新机器人，先不运动。读取插件接入指南，建立逐机证据记录；先检查官方接口、SDK与查询频率，再核对关节和IMU标定。通信或温度异常时停止后续实体试验并保存证据，需要现场配合时再提示我。不要把旧机器或旧模型的通过状态复用到本机。

典型反例与正确处理：

|学生提问/情境|Qoder应如何处理|
|---|---|
|“上次站了30秒，这台直接跑”|核对设备、标定、模型与源码；旧结果不能转移|
|“返回-1，填零继续”|保留失败与原始回包，不冒充有效位置|
|“过期了，就把超时调大”|先量完整控制链和数据年龄，修复后重新仿真/影子|
|“模型completed，所以比基线强”|读取同源评测，区分运行状态和质量|
|“已经打开回放，所以播放通过”|需要宿主实际播放观察，链接不是播放事实|
|“再试一次总能成功”|未知物理结果不自动重试，先确认状态和停止原因|
|“机器人站着等我改代码”|断电阶段准备代码/依赖/提示；上电只跑已准备窗口|
|“装了插件为什么还要登录”|本地知识/证据字段审查无需登录；平台数据与Qoder模型账号分别按服务需要认证|

在完整便携插件内，可调用 `rdk_classroom_guide` 读取课堂规则，调用 `rdk_robot_onboarding_guide` 读取接入流程，再用 `rdk_robot_acceptance_assess` 检查逐机记录。本地字段检查不验证收据真实性，不签发运动许可，也不执行自动标定。


原始协议、SDK、URDF、策略和完整工程源码在独立 OriginMan资料包_20261105.zip 中。本插件提供知识及摘要索引，不将这些资产自动加载到机器人。
